## 第一阶段接口限制

- 下单要求 Idempotency-Key；复用同键时请求体必须相同。
- 库存预占目前只实现 LIST（原价）且 quantity=1；议价模式未开放。
- 当前商品发布只支持基础字段，完整分类/成色/图片和搜索推荐将随商品模块继续迁移。
- 创建中返回 202，客户端使用订单 ID 查询；失败订单返回 409 并携带创建状态。重复取消不会重复加库存。
- 内部预占/确认/释放当前统一返回 200；与目标清单首次预占 201 的细节尚需统一。
- 订单详情当前返回第一阶段简化 DTO，不能作为旧 OrderDetail 的兼容替代；买家权限已校验，卖家/管理员详情后续迁移。
- 地址选择、通知投影、outbox、支付持久化及完整 admin 端点均未实现，不用空实现或跨库查询伪装完成。
- 内部接口路径已受 JWT 验证和逐入口调用方约束；更细粒度 scope、TLS 及生产凭证轮换属于后续安全配置。
- 当前恢复器固定间隔重试，且每次处理最多 50 条；并发安全依靠幂等和状态条件更新，尚无租约、指数退避或告警平台。

### 新增测试用例说明

| 用例 | 主要操作 | 已设置的断言 |
|---|---|---|
| 注册登录及当前用户 | 注册邮箱账号、登录、携带令牌查询 me | 注册 201、登录 200，me 的用户 ID 与注册结果一致 |
| 重复注册事务回滚 | 同一邮箱重复注册 | 第二次 409，users 行数没有增加 |
| 错误密码与匿名访问 | 错误密码登录、不带令牌访问 me | 均返回 401 |
| 身份失效版本 | 签发令牌后提高数据库 token_version，再做内部校验 | 返回 active=false |
| 非法输入与内部匿名访问 | 非法邮箱注册、匿名访问内部用户批量查询 | 分别返回 400、401 |
| 库存幂等 | 两次预占、一次确认、两次释放 | 仅扣一次库存，确认不扣库存，释放仅恢复一次 |
| 同键不同请求 | 同一预占操作号更换买家 | 409，库存不再减少 |
| 释放先于预占 | 先发送释放，再发同键预占 | 预占 409，库存不减少 |
| 最后一件并发抢购 | 六个不同操作并发预占一件商品 | 恰好一个成功，其余冲突，库存为 0 |
| 审核下架保护 | 售罄后标记审核下架，再取消释放 | 库存恢复，但商品仍为 OFF_SALE |
| 内部身份边界 | 缺少凭证、错误调用服务、错误受众 | 分别为 401、403、401 |
| 库存绑定与参数校验 | 用错误订单释放、用零数量预占 | 分别为 409、400，库存不改变 |
| 同订单重复操作号 | 第二个操作号试图预占同一订单 | 409，不再次扣库存 |
| 同键并发重试 | 六个线程同时提交相同预占操作号与请求体 | 六次均返回 200 和相同预占号；只有一条预占记录，库存只扣一次 |
| 匿名下单 | 有请求体和幂等键但无用户令牌 | 401，订单表仍为空 |
| 非法收货信息 | 空收货人、电话和地址 | 400 |
| 内部订单查询权限 | 匿名调用、用户服务越权调用库存状态接口 | 分别为 401、403 |
| 三服务完整首阶段链路 | 注册两个账号、发布、下单、重复下单、取消和重复取消 | 同键返回同一订单；库存只扣/还一次；取消事件仅一条 |
| 订单所有权 | 其他买家读取或取消订单 | 都返回 404，库存仍保持已占用 |
| 响应丢失及重启恢复 | 真实商品服务处理预占后丢弃响应，重启交易服务并恢复 | 初次 202；重启后 WAIT_PAY/CONFIRMED；库存只扣一次 |
| 跨库权限拒绝 | 三个运行账号分别访问另外两个数据库，执行 SELECT/INSERT/UPDATE/DELETE | 24 个越权尝试全部抛出数据库权限异常，写入语句使用零行条件避免副作用 |
| 三服务就绪检查 | 访问各服务 readiness，检查自身数据库 | 三个服务均返回 200 和 UP |
